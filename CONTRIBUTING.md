# Contributing to SlideOps

Thank you for your interest in SlideOps. This guide covers how we work across the organization.

## Ways to help

- Report a bug with clear steps to reproduce.
- Propose a Capability or a Provider for a distribution or tool you rely on.
- Improve documentation and guidance copy.
- Pick up an open issue and send a pull request.

## Ground rules

- Use the shared language. An Operator manages Nodes. A Capability expresses an outcome. A Provider implements it. An Operation is one run of a Capability. Verification proves the result.
- Keep changes focused. One concern per pull request.
- Write clear, plain commit messages. Conventional style with a scope is welcome, for example `feat(provider): add apk package provider`.
- Add or update tests for behavior you change.
- Follow the coding standards in each repository README.

## Pull requests

1. Create a branch from the default branch.
2. Make your change with tests and documentation.
3. Make sure the build, lint, and tests pass locally.
4. Open a pull request that explains the what and the why.

A maintainer will review with an eye on correctness, simplicity, readability, and tests. Reviews are collaborative, not gatekeeping.

## Code of conduct

By taking part you agree to uphold our [Code of Conduct](CODE_OF_CONDUCT.md).
